## Known limitations to state in the release

- The Agent "Needs review" claim check is a **text heuristic**: an answer
  phrased in a way it does not recognise can still end as Completed (F-17 and
  the beta note).
- **F-14:** project-folder grants made before the root guard existed are not
  re-checked; remove and re-add them (ADR 0026). A fresh 0.4.0-Alpha install
  has no such grants.
- Low findings from the qualification run, for a follow-up, not release
  blockers:
  - the Models screen shows a generic **"Download failed."** that hides the
    native reason (for example `MODEL_BUSY` or `INSUFFICIENT_STORAGE`);
  - starting a **second download pauses the first** without warning before
    the click (consistent with the one-transfer design);
  - **"Free storage"** on the Models screen does not refresh after a download.
- Backup restore is not verified on a clean machine (G4).
- MCP is Beta and tools-only; local MCP servers are not sandboxed; there is no
  background agent service; gpt-oss-20b is import-only.
- The Juniper 1 local import is a research experiment, not a qualified or
  production model, and is not Juniper's default.
- The Llama 3.x and Gemma 3 catalog entries are held (G7); a GGUF the user
  obtained can still be imported.

## Release workflow

`.github/workflows/release.yml` runs on the pushed tag `v0.4.0-alpha.1`. Its
contract job refuses a non-prerelease version and reads the release title from
`display_name` in the manifest; `scripts/check-version.mjs` requires that name
to start with `Juniper 0.4.0-` and the manifest to say `prerelease: true`. The
publish job creates a GitHub release named **Juniper 0.4.0-Alpha** with
`prerelease: true`, `make_latest: 'false'` and `draft: false`, and uploads the
five artifacts (`Juniper-0.4.0-alpha.1-linux-x86_64.deb`,
`Juniper-0.4.0-alpha.1-linux-x86_64.AppImage`,
`Juniper-0.4.0-alpha.1-windows-x86_64.msi`,
`Juniper-0.4.0-alpha.1-android-universal.apk`,
`Juniper-0.4.0-alpha.1-android-native-symbols.zip`) with `SHA256SUMS.txt`,
the signing and package notes, `RELEASE-PROVENANCE.json`, `LICENSE` and
`THIRD_PARTY_NOTICES.md` (14 files). Nothing in it marks the release as latest
or stable. The generated notes carry the platform statuses and the limitations
above.

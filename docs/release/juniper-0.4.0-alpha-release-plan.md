# Juniper 0.4.0-Alpha release plan

Status: plan, written on Saturday, October 17, 2026 (EDT) on the "Fixing Up A
Little" branch (PR #49). Nothing here has been tagged, built for release, or
published. Merge, tag, and publication are the owner's decisions.

| ------------------------- | --------------------------------------------------------------------- |

"Juniper 0.4.0-Alpha" is the name used in prose, release notes, and on the
website. Every machine-checked place uses `0.4.0-alpha.1`; the diagnostics
label must read `Juniper 0.4.0-alpha.1` literally because
`scripts/check-version.mjs` compares it.

### Version table

`scripts/lib/version-scheme.mjs` derives the platform numbers and
`scripts/check-version.mjs` enforces them (tests: `scripts/check-version.test.ts`):

| Machine version | Android versionCode      | MSI version           |
| --------------- | ------------------------ | --------------------- |
| `0.3.0-rc.N`    | 3000 + N (rc.33: 3033)   | `0.3.0.N`             |
| `0.4.0-alpha.N` | 4000 + N (alpha.1: 4001) | `0.4.0.N`             |
| `0.4.0-beta.N`  | 4300 + N                 | `0.4.0.(300 + N)`     |
| `0.4.0-rc.N`    | 4600 + N                 | `0.4.0.(600 + N)`     |
| `0.4.0` (final) | reserved: 4900           | reserved: `0.4.0.900` |

N runs from 1 to 299 for 0.4.0 prereleases. A bare stable version such as
`0.4.0` is rejected by the check until the final release is decided and the
table is extended. Later lines (0.5.0 and on) follow the same pattern from
MINOR × 1000.

Known limit, unchanged from the 0.3.0 candidates: Windows Installer compares
only the first three fields of a version when it decides whether a package is
an upgrade. `0.4.0.1` upgrades `0.3.0.33`, but a later `0.4.0.x` package is
not recognised as newer than `0.4.0.1` by the major-upgrade rule; uninstall
the earlier 0.4.0 prerelease first, as for the rc series.

## Expected release files

The release workflow (`.github/workflows/release.yml`) must publish exactly
these 14 files, which `manifests/release-candidate.yaml` lists:

- `Juniper-0.4.0-alpha.1-linux-x86_64.deb`
- `Juniper-0.4.0-alpha.1-linux-x86_64.AppImage`
- `Juniper-0.4.0-alpha.1-windows-x86_64.msi`
- `Juniper-0.4.0-alpha.1-android-universal.apk`
- `Juniper-0.4.0-alpha.1-android-native-symbols.zip`
- `SHA256SUMS.txt` (covers every file above)
- `SIGNING-android.txt`, `SIGNING-windows.txt`
- `PACKAGE-android.txt`, `PACKAGE-linux.txt`, `PACKAGE-windows.txt`
- `RELEASE-PROVENANCE.json`
- `LICENSE`, `THIRD_PARTY_NOTICES.md`

The manifest's `publication.state` is `not-yet-published` until the release
exists; after publication, record the run, tag commit, and file digests in a
`docs/release/0.4.0-alpha.1-publication.md` record in the style of
`rc33-publication.md`.

## Signing status (disclose in the release notes)

- **Windows MSI: unsigned.** No Authenticode certificate is configured;
  `SIGNING-windows.txt` records the unsigned status. SmartScreen will warn.
- **Android APK: signed** with the existing release key through the
  workflow's signing secrets (`docs/release/android-signing-runbook.md`);
  `SIGNING-android.txt` records the certificate.
- **Linux DEB and AppImage: not signed**; integrity is by `SHA256SUMS.txt` and
  GitHub artifact attestations.

## Platform statuses for the release notes

| Platform             | Status                                                                                                                                                                                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Linux x86_64 desktop | Alpha. Chat, Models, Settings, and Agent (Beta). Launch verified on X11 (Ubuntu 22.04 and 24.04 in CI); native Wayland not verified. The Agent code sandbox (bubblewrap) is Linux-only.                                                                                                              |
| Windows 10/11 x64    | Alpha. MSI install, render, and uninstall smoke in CI. **Agent execution on Windows is not verified**; sandboxed code is unavailable there by design. MSI unsigned.                                                                                                                                  |
| Android 7.0+         | **Beta** for native local inference. Package, emulator, and instrumentation evidence only; **a physical ARM64 inference run with build identity and device details is still required** before Android inference can leave Beta. Agent project folders and sandboxed code are unavailable on Android. |
| macOS, iOS           | Not built.                                                                                                                                                                                                                                                                                           |

Other limits to repeat: MCP is Beta and tools-only; local MCP servers are not
sandboxed; there is no background agent service; gpt-oss-20b is import-only;
the Juniper 1 local import is a research experiment, not a qualified or
production model.

## Release checklist

1. PR #49 has a fresh independent re-review with no blocking finding, and the
   owner has merged it. Remaining evidence gaps from the 2026-10-16 review
   (F-05) are either closed or stated in the release notes:
   - `scripts/live-transfer-check.sh` re-run on an idle disk with at least
     6.2 GB free, by someone other than the implementer;
   - a native-application workflow pass by someone other than the
     implementer (a FLOWBOX X11 debug build is enough);
   - a restore on a clean machine (not yet run by anyone).
2. The owner records a decision on the third-party GGUF mirrors used for the
   Llama 3.x and Gemma 3 entries (review F-02 note) before those entries ship.
3. On the merge commit: `pnpm validate` and `pnpm build` pass locally, and the
   `validation` workflow passes in full, including the
   `agent-sandbox-evidence` artifact ("6 passed; 0 failed", no skip line).
   Dispatch the manual Android inference job if emulator inference evidence is
   wanted for the notes.
4. A release-readiness review is written to
   `docs/qualification/release-readiness-review-<date>.md` (as for
   2026-09-22), covering this checklist.
5. Create the annotated tag `v0.4.0-alpha.1` on the merge commit and push it.
   The release workflow checks `RELEASE_TAG` against `check-version.mjs`,
   builds, smokes, signs, attests, writes `SHA256SUMS.txt` and
   `RELEASE-PROVENANCE.json`, and publishes an immutable prerelease.
6. Download every published file, check it against `SHA256SUMS.txt`, run
   `gh attestation verify` on each executable, and confirm the asset list
   equals the 14 files above, nothing extra.
7. Write the publication record and set `publication.state: published` in the
   manifest in a follow-up change.
8. Update the website (below) in the cinqic.com repository, then run its
   link check.
